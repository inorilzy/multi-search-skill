关键边界与代码依据
  • 摘要、预览、缓存全文分开：results[].content 是搜索摘要；正文在 scrapes[].markdown，默认预览 1200 字符，以 source_id 关联。multi_search 的 Markdown/both 模式只在顶层 markdown 放正文。service.py 负责共享流程和展示；正文失败保留排名。
  • 获取顺序：解析来源并校验 URL → source-ID 缓存 → 条件允许的 URL/scope 缓存 → Provider 预取正文或实际抓取。URL/scope 复用仅适用于无预取正文的请求，受来源、后端及权限范围约束。fetch_source(full_content=True) 返回已取得全文；ContentStore 仍受保留策略、大小和过期限制。预览缩短不会截短已存正文。
  • read 仅缓存：缺失或过期时明确报错，不发起抓取；读取仍会维护访问时间及清理过期数据。use_state=False 跳过 SQLite，公共 source-ID fetch/read 需要状态；直接 URL fetch 仍可用。scrape_url 不建立 source-ID 正文缓存。
  • 入口与配置：Skill 指导工具选择；配置文件、环境变量与 keys 文件提供行为配置和凭据。MCP 的搜索/抓取经 tools.py 进入 Core，CLI search/fetch/read 直接调用 Core；key/site 管理工具也会直接访问状态类。图不把明文凭据画入 SQLite。
  • MCP 调度：server.py 将 search_web、multi_search、fetch_source、scrape_url 转交独立 4 槽位有界线程池，再调用同步工具与 Core。满池返回明确的 runtime_error；取消等待不能中止正在运行的线程，工作实际结束才释放槽位，Core deadline 仍有效。轻量工具不进入这个池。
  • 预取正文只选一次：候选阶段按 URL 生成 prefetched_bodies；最长正文优先，等长时按 provider、正文文本升序选择。缓存写入与当前响应复用同一结果；use_state 控制持久化，不改变这个选择。
  • Exa 错误边界：adapter 区分目标网页错误与 provider 凭据错误。目标失败保留使用记录及明确错误，不触发 key 健康转换或 key 轮换；provider 认证/额度/限流仍由 key manager 分类处理。
  • 非生产路径：旧 ScrapePlanner / run_scrape_stage 与正文回写链已删除；当前生产使用 run_ranked_fetch_stage。格式化仍使用 rank_results；scrape_top / scrape_per_source 兼容参数仍被接受，但不限制最终正文获取。provider_runs 只有建表，没有生产写入；scrape_attempts 由 SiteScraperMemory 写入。快照采集与回放 是显式开发工具，不是生产缓存层。带日期的历史审查图保持原语境。
